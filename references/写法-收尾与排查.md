## 5. 三种成品形态

三种形态就是笔法在块上的不同分配，都成立：

| 形态 | 分配 | 适合 |
|---|---|---|
| **A 词组块 + 句子块** | 主体锚/镜头/姿势用词组，关系/场景/光影用句子 | **默认**，可控性与表现力平衡最好 |
| **B 词组织进句子** | 混在同一行逗号并列 | 内容零散、有具体 UI/文字要求时 |
| **C 纯句子** | 全部自然语言 | 画面是完整场景叙事，或写风格调性 |

官方各有实例：A 见示例 #1（空行分十段），B 见 #4，C 见 #2 和 #5。

## 6. 质量词与负面词

**质量词**：前端画质预设会自动附加三个词——审美词、杰作词、禁文字词
（`very aesthetic` / `masterpiece` / `no text`，**这里列出来是让你认得它们、
好在产出里避开，不是让你抄**）。

> **这三个词出现在你的产出里就是重复注入**，等于把同一个词的权重叠了两遍。
> 默认一个都不写。只有用户明确要更高完成度时，才追加**预设没有的**那几个：
> `best quality` `amazing quality` `absurdres` `ultra detailed`（放整条最末尾）。
`high/ultra complexity` **不属于质量尾**——它是功能开关，默认不加，
规则见开篇「V5 开关」与 §3.10。

**UC 只有两档，二选一**：

- 没有要排除的 → 写一行「用默认预设」，**到此为止**
- 有要排除的 → **只写排除项本身**，预设串照样不抄——前端会把预设和你的排除项拼在一起。
  例：`nsfw`（要 SFW）· `muted color, pale color, flat color`（要浓色）·
  `oiled skin, shiny skin`（不要油光）

画面里明确不想要的具体元素，**直接负权重写进正文更准**，比堆进 UC 有效。
**多人图检查预设段**：群用 UC 预设里 `2::…extra characters…::` 那段是给 solo 图的，
多人图必须拿掉（§4.9）——排除项档里也**不写 `extra characters`**。

> 语料里那批 95–99% 出现率的 UC 词是前端预设带进来的，**不是群体共识**，
> 别当统计发现引用。（脚注：官方 12 条示例 12/12 手写 UC——那是**没有前端预设的
> API 场景**的做法，不是「要手抄预设」的示范；前端环境预设常开，按上面两档来。）

## 7. 参数（仅在用户询问或排查时给，不随 prompt 输出）

| 参数 | 建议 | 实测 1844 条 |
|---|---|---|
| Steps | 28 | 28 **80%** · 23 16% |
| Sampler | `k_euler_ancestral` | 90% |
| Noise Schedule | `karras` | **98%** |
| Guidance | 无共识，5.0–7.0 都常见 | 5.0 21% · 7.0 21% · 5.5 18% |
| Prompt Guidance Rescale | **官方口径 0.0** | 0.0 **41%** · 0.4 23% · 0.2 17%；**官方 12 条里 11 条是 0.0** |

> `cfg_rescale` 曾在老口径（判归 957 条）里显示 0.4 占 39%、像是「群口径 vs 官方口径」
> 的分叉；**全库 1844 条重算后 0.0 反而是第一（41%）**——0.4 只是其中一批人的习惯，
> 不是全群共识。拿不准用官方的 0.0，这条现在有两边背书。

N5 教程口径（并记，与群实测互参）：steps 23–28（**28 是免费临界**，29 步开始收点）；
guidance **4.5–6.5**；PGR 是高 guidance 时的纠偏器，日常不推荐动；
**Variety+** = 「说完要求后允许模型假装没听见一小部分、自己发挥」——想要多样性
优先开它，而不是降 guidance（那会整体降提示词权重、连风格一起变）。

尺寸：竖 832×1216（最常用）· 1024×1536；方 1024×1024；横 1216×832 · 1536×1024。
构图只说方向（竖/横/超宽/方），不写像素。
最高档会员**长×宽 < 约 108 万像素免费**；手动调整时按 32/64 步长自动修正。

**额度条（自动化 agent 要用）**：25 刀档的 v5 免费小图走额度条——充满约
**1600–1700 张**，以约 11%/天（≈190 张，7.5 分钟一张）持续回复，订阅周期首月最多
充满 3 次；第二个月起不再当日充满、改约 13%/天（≈230 张）回复。
**断订当天收回额度条、赠送点数直接清零**。挂机跑图按「额度条余量」做预算，
不要只看 Anlas。

## 8. 排查

| 症状 | 处理 |
|---|---|
| **姿势画糊、多出一条腿** | **姿势那段写成句子了**。改 tag（`sitting, leg up, arm support, head rest`）。最高频失败模式 |
| **机位压不低** | 句子推不动机位，加 `from below`。三个镜头 tag 别一起上，会盖掉姿势 |
| **袜子/手套形制或数量不对** | 先查中文释义。`loose socks` 是堆堆袜、`single thighhigh` 是只穿一只，都会静默换衣服。要「一只拉起一只滑下」**用句子写状态**（`uneven legwear` 单独写推不动，实测 0/3） |
| **整张图变成一片纹理／泥浆** | 画师名或 tag **以数字结尾**又紧跟 `::`——`na_tarapisu153::` 会被解析成权重 **153**，整条提示词被炸掉。写成 `na_tarapisu153, ::`——**加逗号比加空格更安全**，哪怕多打一个变成 `2::artist:na_tarapisu153, ::,` 也比 `na_tarapisu153 ::` 稳 |
| tag 被忽略 | 提权重 / 移到前部 / 拆成独立 tag / 改用整句 |
| 画面平、缺层次 | 补光影层（主光方向 + 投影形状）；色彩层次差加主题色 |
| 色调不符 | 加主题色或 `limited palette`；色彩词前移 |
| 逆光面部过暗 | `-2::backlighting::` 或补 `front lighting` / `face lighting` |
| 角色白背景虚空 | `-1::simple background::` + 明确写场景 |
| 多角色串味 | 句子写死归属 + 编号对应画布定位 + 检查人数 tag 位置 |
| 动作僵硬 | 句子写进行中的状态 + 衣物头发被动响应。**但姿势本身用 tag** |
| 场景糊成抽象物 | 清单后补整体性要求句 |
| 透视不对 | 机位用 tag，前后压缩用对比句式 |
| 想强调腿但出不来 | 别堆 `thighhighs, bare legs`，也别用 `leg focus`（266 太弱）。`from below` 压机位 + 句子写占画幅；要到脚就 `foot focus` |
| 文字不出/出错 | 引号包裹 + 句子写清**载体**和位置；仍不出再试 UC 去掉 `no text` 或正文 `-1::no text::`（默认不用动它）；别手写 `Text:` 块 |
| 出来太"通用"没个性 | 主力档挑太多了。往常见/可选档挪 |
| 固定物体始终画不对 | 模型知识盲区，换构图思路，别堆 tag |

## 9. 写完对照

每条后面是它的依据。**发出去之前把这张表过一遍**——压测里 90% 以上的违规
都落在这张表能拦住的范围。

| 检查 | 依据 |
|---|---|
| 姿势那块是词组，不是句子 | 出图实测 4/4（跨两条画师串） |
| 机位高低用 tag，不是句子 | 出图实测 3/3 成立 vs 3/3 失败 |
| 角色外貌 / 服装 / 角色名在角色栏，不在主提示词 | 861 条实测的分工：发型 66% vs 11%、服装 68% vs 37% |
| 人数 tag 在最前且只出现一次 | 领先多数类 67–97%（n=527–807） |
| 质量词写在主提示词末尾，没有包 `<quality>` 块 | `<quality>` 在 1844 条里仅 1 条 |
| 服装状态词查过中文释义 | 踩过坑：`loose socks` 是堆堆袜，12 张全中招 |
| 句子只在写关系，没在写离散事实 | 同第 1–2 条的实测 |
| 背景形态只选了一种 | 未实测，是 tag 语义上的互斥 |
| 多人时用句子写死归属 | 未单独实测；多人串味的常见成因 |
| 没有凭印象给角色分配职能 / 乐器 / 身份 | 踩过坑：MyGO 五人写反两个（§4.2） |
| 要分配就查过 wiki 身份词，或算过 lift 且 ≥1.3 倍 | 9 角色实查：原始占比错 2 个，lift 错 1 个 |
| **多人图的 UC 里没有 `extra characters`**（预设那段拿掉了） | §4.9：权重 2 的「多余角色」跟人数 tag 打架；压测 39/103 栽在这 |
| 取景距离只挑了一个，视线方向只挑了一个 | §3.9 互斥组；语料 20–22% 犯此错 |
| 人数 tag 与角色栏格数一致（`2girls` ↔ 恰好两格） | §0 常见错 5 的下游实测 |
| 三人以上或有前后景层次时，附了 Position 建议行 | §4.9 实测：文字写不动层次，控件一次成功 |
| UC 是「排除项」或「用默认预设」二选一，没抄预设串；质量尾没重复预设已带词 | §6 两档规则；压测 103/103 栽在抄预设 |
| **每个角色栏的第一个词是性别词**（`girl`/`boy`/`other`，不带数字） | 两份语料合计 926/1010 = 92% 这么写 |
| **版权角色的角色栏只有性别词+角色名**（作品名可选），没有再列发色/发型/眼睛 | §0「原创 vs 版权」表；用户报的 bug，五人图实测五格全多写 |
| **原创角色用户给的样貌锚点一个没少**（发色/发型/瞳色/体型/种族特征/耳朵/角/尾巴/翅膀/标志性饰品） | §0「原创 vs 版权」表；用户报的 bug，反方向 |
| 漫画有台词时，**每句写在它所属那一格的句子里**，并说清载体；无台词的格明写 `No text` | §「漫画（语法侧）」；用户报的 bug：图文错位 |
